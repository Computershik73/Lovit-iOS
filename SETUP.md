# Как собрать «Ловит»

Клиент мессенджера MAX для **iOS 6 и новее**. Objective-C, UIKit, без
storyboard и внешних зависимостей. **Mac и Xcode не нужны** — собирается
в Linux или в WSL 2 через Theos.

Нужно: Ubuntu или Debian (`setup.sh` ставит пакеты через `apt-get`; в другом
дистрибутиве поставьте их сами — список ниже), x86_64, интернет на первый
запуск и несколько гигабайт свободного места на время установки: набор SDK
качается целиком, а нужен из него один. В WSL исходники можно держать и в
файловой системе Linux, и на диске Windows — работает и так, и так.

Здесь только порядок действий. Почему всё устроено именно так — в
[README.md](README.md); там же разбор ловушек, на которых этот порт
спотыкался.

---

## Одной командой

```bash
sh tools/setup.sh
make ipa FINALPACKAGE=1
```

Первая команда ставит всё недостающее и занимает минут пятнадцать, из них
десять — сборка OpenSSL. Запускать её повторно безопасно: каждый шаг сначала
проверяет, не сделан ли он уже.

Получается `packages/Lovit.ipa` — универсальный, armv7 и arm64.

## Что именно ставится

| Шаг | Куда | Зачем |
|---|---|---|
| пакеты `git curl perl make python3 zip dpkg-dev` | системой | perl нужен самому Theos, `dpkg-deb` — пакету, `zip` — ipa |
| Theos и тулчейн | `~/theos` | сборочная система и clang для iOS |
| `iPhoneOS9.3.sdk` | `~/theos/sdks` | последний SDK с заголовками эпохи iOS 5–6 и срезом armv7 |
| заплатки к SDK | там же | **обязательны**, см. ниже |
| OpenSSL 1.1.1w | `~/lovit/out` | своя криптография, см. ниже |
| libopus 1.4 | `~/lovit/opus` | голосовые, см. ниже |
| rlottie 0.2 | `~/lovit/rlottie` | движущиеся стикеры, см. ниже |

## Два места, где легко обжечься

**Заплатки к SDK — не украшение.** Набор `.tbd` из
[theos/sdks](https://github.com/theos/sdks) перегенерирован, а не взят
у Apple, и при перегенерации потерялась часть символов; заодно там объявлены
привязки классов, верные для iOS 9 и неверные для iOS 6–7. Без
`tools/patch-sdk.sh` сборка либо не линкуется, либо — что хуже — линкуется
и снимается dyld'ом на устройстве ещё до `main`, без записи в журнале падений.
`setup.sh` вызывает его сам; при обновлении SDK запустите заново.

**Криптография своя, и это вынужденно.** Сервер MAX согласовывает TLS 1.3,
а на TLS 1.2 из шифров эпохи iOS 6 принимает ровно один. Secure Transport той
поры его не предлагает, и рукопожатие не складывается вовсе — приложение
просто не соединяется. Поэтому `tools/build-openssl.sh` собирает OpenSSL
по срезу на архитектуру, с нижней границей 6.0.

**Кодек голосовых — тоже свой, и по той же причине.** Голосовые в MAX ходят
в Opus внутри Ogg, а этого кодека на iOS 6 нет: `AVAudioRecorder` умеет только
AAC и линейный PCM, системный проигрыватель такой файл не открывает. Ни
записать, ни послушать голосовое без своей библиотеки нельзя. Собирает её
`tools/build-opus.sh` из исходников в `third_party/opus` — качать ничего не
надо, и занимает это пару минут:

```bash
sh tools/build-opus.sh
```

Настройки — в `third_party/opus/config-ios.h`, а не в `configure`: кросс-сборка
автотулзами под iOS из Linux настраивается долго и норовит нащупать не тот
компилятор, а список файлов у libopus известен и невелик. Оптимизации под
armv7 и arm64 не берутся намеренно — у них свои правила сборки и ассемблерные
файлы, а голос кодируется и обычным C заметно быстрее реального времени.

**И отрисовщик стикеров.** Движущийся стикер — это Lottie: не картинка, а
описание векторной сцены во времени. Рисует её rlottie, та же библиотека, что
рисует такие стикеры в Telegram. Собирается так же:

```bash
sh tools/build-rlottie.sh
```

Два места, о которых стоит знать. Первое: rlottie написана на C++14, а в SDK
лежит только libstdc++ 4.2.1 времён GCC — поэтому заголовки libc++ берутся у
тулчейна (`-nostdinc++ -isystem …/include/c++/v1`), а сама библиотека на
устройстве системная. Второе: обёртка для C своя
(`third_party/rlottie/max_lottie.cpp`), а не та, что идёт с библиотекой: та
тянет подмену свойств сцены, определений которой в этой копии нет вовсе.

## Проверка результата

```bash
python3 tools/check-macho.py packages/Lovit.ipa
```

Смотрит в готовый бинарник: обе ли архитектуры на месте, та ли нижняя
граница, тот ли SDK, в порядке ли подпись — и, главное, не просит ли код
какой-нибудь класс `NS*` не у той библиотеки. Последнее и есть та ошибка,
которая иначе всплывает только на живом телефоне.

Про подпись он проверяет именно то, что легко потерять: в ней должно быть
**два** описания кода — SHA-1 для iOS 6–9 и SHA-256 для iOS 11 и новее.
Поэтому `ldid` зовётся без ключа `-H`: с ним он кладёт только одно. Почему
так — в README, раздел «Подпись: две сводки, а не одна».

## Установка на устройство

Устройство должно быть с джейлбрейком: подпись adhoc, своего сертификата
разработчика тут нет.

* `.ipa` — через 3uTools, Sideloadly или любой установщик, понимающий
  неподписанные пакеты;
* `.deb` из `packages/` — через Filza или `dpkg -i` по SSH.

Номер сборки растёт сам при каждой упаковке (`CFBundleVersion`), поэтому
установщик всегда видит новую версию. Увидеть его можно в «Настройки →
О приложении».

## Журнал для отладки

В обычной сборке журнал выключен: в него попадает переписка — имена, тексты,
адреса вложений, — а папка `Documents` у приложения открыта наружу. Для
отладки включите обе константы в `src/MAXLog.h`:

```c
#define MAX_LOG_TO_FILE 1      // Documents/max.log, виден в iTunes и «Файлах»
#define MAX_LOG_TO_SYSLOG 1    // системный журнал
```

Такую сборку не раздавайте. Строки о падении («[ПАДЕНИЕ]») уходят в системный
журнал при любых значениях — переписки в них нет.

## Правки в коде

* значки рисуются вектором в рантайме — `src/UI/Icons/MAXIconData.m`,
  генератор `tools/gen-icons.py`;
* иконка приложения и экраны запуска — `tools/gen-icons.py` из
  `tools/icon-source.jpg`;
* всё оформление — `src/UI/MAXTheme.m`; ни один экран не красит себя сам;
* протокол и опкоды — `src/Core/Protocol/`, модули — `src/Backend/`.

## Чего в архиве нет

Скриншотов — там переписка с живыми людьми. Каталогов сборки (`.theos/`,
`packages/`) — они получаются заново. Сводок к отдельным сборкам и плана
работ — они про ход разработки, а не про код.
